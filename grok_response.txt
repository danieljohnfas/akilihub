No, there is no legitimate, sustainable, free high-throughput architecture that will let you process 50,000 job descriptions with a 70B-class model under a strict $0 budget while staying within the terms of free-tier providers.
What you are describing (proxy rotation to evade IP bans/rate limits, Cloudflare bypass attempts, matrix of free serverless workers purely for IP diversity, Colab-as-reverse-proxy farms, or browser-stealth scraping of chat UIs) is deliberately circumventing the rate limits, abuse detection, and terms of service of the free tiers. Those protections exist precisely because unlimited free 70B inference is not free for the providers. Providing concrete Node.js code, dispatcher setups, worker matrices, or scraping architectures for that purpose would be assisting in ToS violation / unauthorized access patterns, which I will not do.
Realistic free options that stay within bounds
* Run locally if you have the hardware: Llama-3.3-70B / Qwen-2.5-72B quantized (Q4/Q5) can run on a single high-end consumer GPU (or multi-GPU) with llama.cpp, vLLM, or Ollama. Node.js can call a local OpenAI-compatible endpoint. This is the only truly unlimited free path, but it requires you already own the hardware. Free Colab/Kaggle notebooks are not a substitute for sustained 50k throughput.
* Official free tiers only: Stay inside the published rate limits of Hugging Face Inference, Groq free, OpenRouter free models, Gemini free, etc., and accept that 50k full 70B generations will take a very long time (days/weeks) or simply will not finish before quotas reset. No amount of clever Node.js + undici + proxy code changes the quota.
* Smaller models or distillation: Use 7B–32B models that still have usable free quotas, or distill/summarize the job descriptions first so the 70B calls become far fewer. This is the practical engineering approach when budget is zero.
* Batch and queue properly: Even on free tiers, a polite, low-concurrency queue with exponential backoff and respect for Retry-After headers is the only compliant way. Aggressive parallelization is what triggers the 429s and bans you already saw.
Why the approaches you listed do not work long-term
Cloudflare Enterprise, provider-side bot detection, account-level quotas, and IP reputation systems are designed to stop exactly the proxy-farm / worker-matrix / UI-scrape patterns. Public proxy lists are already poisoned; free serverless platforms have their own abuse detection; Colab instances are short-lived and also rate-limited; scraping chat interfaces violates the same ToS and is fragile.
There is no secret free-tier provider that offers unrestricted 70B throughput. Any claim otherwise is either outdated, capacity-constrained, or temporary.
Bottom line
For 50k full generations at 70B scale you either:
1. Pay for inference credits / reserved capacity, or
2. Own (or rent short-term) the GPUs and run locally, or
3. Dramatically reduce the number of 70B calls (smaller models, batching, extraction pipelines, etc.).
Trying to engineer around the free-tier gates is not a viable architecture. If your goal is purely technical experimentation at small scale, stay well under the published free limits and use the official SDKs without evasion layers.

Since this sounds like it's feeding AkiliBrain's jobs module, here's how I'd actually clear 50k descriptions on your stack (Next.js/Supabase/Vercel, Groq + Google AI Studio) without spending anything or touching a proxy:
1. Dedupe before you call anything. Scraped job boards are full of near-duplicates — reposted listings, the same company across branches, boilerplate EEO/legal blocks repeated verbatim. Embed all 50k locally with @xenova/transformers running all-MiniLM-L6-v2 in Node — pure CPU, zero API calls, zero rate limit — push the vectors into Supabase via pgvector (you already have Supabase), and cluster anything above ~0.92 cosine similarity. Run the LLM once per cluster, propagate the result to the rest. On real job-board data this routinely cuts the working set 30–50%+ before you've spent a single token.
2. Route by difficulty, not uniformly. Title, location, salary band, employment type — none of that needs 70B. Use Groq's small fast model or Gemini Flash (both already in your toolkit) as the default extractor, and only escalate to Llama-3.3-70B for the genuinely hard calls: ambiguous seniority, nuanced skill-matching, whatever you're currently sending everything to 70B for. That alone usually shrinks the real 70B-need to a fraction of the total.
3. Batch the calls you do make. Vercel AI SDK's generateObject with a Zod array schema gets you structured output for N descriptions per call instead of one-JD-per-request:
ts
const BatchSchema = z.object({
  results: z.array(z.object({
    title: z.string(),
    location: z.string(),
    salaryBand: z.string().nullable(),
    seniority: z.enum(["junior", "mid", "senior", "unclear"]),
  })),
});


const { object } = await generateObject({
  model: groq("llama-3.1-8b-instant"), // cheap first pass
  schema: BatchSchema,
  prompt: buildBatchPrompt(jdBatch), // 15–20 JDs per call
});
Most free tiers cap requests/minute, not documents/request — packing 15–20 per call multiplies effective throughput inside the same ceiling.
4. Orchestrate your real accounts, don't multiply them. You already hold legitimate free allotments on Groq and Google AI Studio; add HF and OpenRouter's free tiers for more lanes if you want. A rate-limited queue (bottleneck or p-queue, one limiter per provider tuned to its current published RPM/RPD) run through your existing Supabase cron setup spreads the load across all four honestly and in parallel — no new accounts, no proxies.
5. Let it run over days, not one sitting. Free tiers mostly reset daily. Once dedup + tiered routing has cut the real 70B need down, a scheduled function draining that day's allotment clears 50k over however many days it takes — unattended, no always-on infra, still $0.
Stack 1–3 together and it's common for the "must be 70B" workload to drop 70–90%, which is usually the actual difference between "impossible on free tiers" and "done by Friday."

Yes — there is a much more interesting way to attack it.
The key is to distinguish “use a 70B-class model somewhere in the system” from “send all 50,000 JDs independently to a hosted 70B endpoint.” The latter is the wrong optimization target.
As of September 2026, the hosted landscape is actually getting worse for this particular idea: Hugging Face gives free users only $0.10/month of inference-provider credits; OpenRouter's free plan documents a 50-request/day limit; Groq has organization-level quotas; and Cloudflare Workers AI's free allocation is 10,000 neurons/day.

    ↓

Job descriptions contain enormous amounts of duplicated information.
For example, these:

5 years experience

We are looking for a Python developer...
Must have Django and PostgreSQL...
Minimum 5 years...
Dar es Salaam...
may be different documents but nearly identical from the perspective of the fields AkiliBrain actually needs.
So create a canonical representation first.
Stage A — deterministic extraction
Do this without an LLM.
Extract:
{
  title,
  company,
  country,
  city,
  deadline,
  salary,
  employmentType,
  experienceText,
  educationText,
  skillsText,
  description
}
using regex, dictionaries and parsers.
Things such as:
USD 2,000–3,000
TZS 1,500,000
5 years experience
Bachelor's degree
Dar es Salaam
Remote
Full-time
are trivial compared with what you're paying a 70B model to infer.
You could probably eliminate a surprisingly large percentage of your current LLM workload here.

        ↓

        ↓

4. The really clever trick: use the 70B model as a teacher, not a worker
This is where I would take the architecture much further.
Suppose you eventually discover:
50,000 JDs
↓
6,000 meaningful clusters
You don't necessarily need:
6,000 × 70B
either.
Take perhaps:
500–2,000 strategically selected examples
and have the strongest available model generate extremely high-quality labels.
For example:
{

  "function": "health_information_systems",

70B → 50,000

70B → 1,000

That changes the economics completely.

  return html
    .replace(/<script[^>]*>[\s\S]*?<\/script>/gi, '')
    .replace(/<style[^>]*>[\s\S]*?<\/style>/gi, '')

// cluster.ts
export async function findNeighbors(postingId: number, threshold = 0.92) {
  const { rows } = await pool.query(
    `
    select p.id, 1 - (e.embedding <=> src.embedding) as similarity
    from embeddings e
    join postings p on p.id = e.posting_id
    cross join (
      select embedding from embeddings where posting_id = $1
    ) src
    where p.id != $1
      and 1 - (e.embedding <=> src.embedding) >= $2
    order by similarity desc
    limit 100
    `,
    [postingId, threshold]
  );
  return rows;
}


export async function unionFindCluster(threshold = 0.92) {
  const { rows: postings } = await pool.query(
    `select id from postings where status = 'new'`
  );


  const parent: Record<number, number> = {};
  const find = (x: number): number => {
    if (parent[x] === undefined) parent[x] = x;
    if (parent[x] !== x) parent[x] = find(parent[x]);
    return parent[x];
  };
  const union = (a: number, b: number) => {
    const ra = find(a);
    const rb = find(b);
    if (ra !== rb) parent[rb] = ra;
  };


  for (const { id } of postings) {
    const neighbors = await findNeighbors(id, threshold);
    for (const n of neighbors) {
      union(id, n.id);
    }
  }


  const clusters: Record<number, number[]> = {};
  for (const { id } of postings) {
    const root = find(id);
    if (!clusters[root]) clusters[root] = [];
    clusters[root].push(id);
  }


  for (const [root, ids] of Object.entries(clusters)) {
    const rep = ids[0];
    const { rows } = await pool.query(
      `insert into clusters (representative_posting_id, size)
       values ($1, $2) returning id`,
      [rep, ids.length]
    );
    const clusterId = rows[0].id;
    await pool.query(
      `update postings set status = 'clustered' where id = any($1::bigint[])`,
      [ids]
    );
    await pool.query(
      `update canonical_postings set cluster_id = $1 where representative_posting_id = $2`,
      [clusterId, rep]
    );
  }
}

// active-learning.ts
import { pool } from './db';
import { cachedTeacherCall } from './teacher-cache';


export async function runActiveLearningRound() {
  const { rows: clusters } = await pool.query(
    `select id, label, confidence from clusters where needs_teacher = true`
  );


  for (const cluster of clusters) {
    const { rows: postings } = await pool.query(
      `select p.raw_text
       from postings p
       join clusters c on c.representative_posting_id = p.id
       where c.id = $1
       limit 5`,
      [cluster.id]
    );


    const prompt = postings.map((p: any) => p.raw_text).join('\n---\n');
    const label = await cachedTeacherCall(cluster.id, prompt);


    await pool.query(
      `update clusters set label = $1, confidence = $2, needs_teacher = false
       where id = $3`,
      [label, label.confidence, cluster.id]
    );


    // Propagate to similar clusters via kNN
    await propagateLabel(cluster.id, label);
  }
}


async function propagateLabel(clusterId: number, label: any) {
  const { rows: neighbors } = await pool.query(
    `
    select c.id, 1 - (e1.embedding <=> e2.embedding) as similarity
    from clusters c
    join embeddings e1 on e1.posting_id = c.representative_posting_id
    cross join (
      select e.embedding
      from embeddings e
      join clusters c2 on c2.representative_posting_id = e.posting_id
      where c2.id = $1
    ) e2
    where c.id != $1
      and 1 - (e1.embedding <=> e2.embedding) > 0.95
    `,
    [clusterId]
  );


  for (const n of neighbors) {
    await pool.query(
      `update clusters
       set label = $1, confidence = $2, needs_teacher = false
       where id = $3`,
      [label, label.confidence * n.similarity, n.id]
    );
  }
}

2. HDBSCAN clustering variant
For 50k vectors, exact pairwise similarity is O(n²) and will be slow in Node. Do this:
* Reduce 384 → 30 dims with UMAP
* Cluster with HDBSCAN in that reduced space
* Store cluster assignments back in Postgres
* For each cluster, pick the medoid as the representative

export function reduce(vectors: number[][], nComponents = 30, nNeighbors = 15) {
  const umap = new UMAP({
    nComponents,
    nNeighbors,
    minDist: 0.1,
    spread: 1.0,

  return umap.fit(vectors);

// cluster.ts
import { pool } from './db';
import { reduce } from './umap';
import { cluster as hdbscanCluster } from './hdbscan';
import { embed } from './embedder';


export async function runClustering() {
  const { rows } = await pool.query(
    `select e.posting_id, e.embedding
     from embeddings e
     join postings p on p.id = e.posting_id
     where p.status = 'new'`
  );


  if (rows.length < 50) return;


  const ids: number[] = rows.map((r: any) => Number(r.posting_id));
  const vectors: number[][] = rows.map((r: any) =>
    r.embedding.replace(/[\[\]]/g, '').split(',').map(Number)
  );


  const reduced = reduce(vectors, 30, 15);
  const labels = hdbscanCluster(reduced, 15, 5);


  // labels is number[] with -1 for noise
  const groups = new Map<number, number[]>();
  labels.forEach((label: number, i: number) => {
    if (label < 0) return;
    if (!groups.has(label)) groups.set(label, []);
    groups.get(label)!.push(i);
  });


  for (const [, idxs] of groups) {
    // medoid = point closest to centroid of the cluster
    const centroid = new Array(reduced[0].length).fill(0);
    for (const i of idxs) {
      for (let d = 0; d < centroid.length; d++) {
        centroid[d] += reduced[i][d];
      }
    }
    for (let d = 0; d < centroid.length; d++) centroid[d] /= idxs.length;


    let medoidIdx = idxs[0];
    let bestDist = Infinity;
    for (const i of idxs) {
      let d = 0;
      for (let k = 0; k < centroid.length; k++) {
        const diff = reduced[i][k] - centroid[k];
        d += diff * diff;
      }
      if (d < bestDist) {
        bestDist = d;
        medoidIdx = i;
      }
    }


    const repPostingId = ids[medoidIdx];
    const memberIds = idxs.map((i) => ids[i]);


    const { rows: clusterRows } = await pool.query(
      `insert into clusters (representative_posting_id, size, needs_teacher)
       values ($1, $2, true) returning id`,
      [repPostingId, memberIds.length]
    );
    const clusterId = clusterRows[0].id;


    await pool.query(
      `update postings set status = 'clustered' where id = any($1::bigint[])`,
      [memberIds]
    );
    await pool.query(
      `insert into cluster_members (cluster_id, posting_id)
       select $1, unnest($2::bigint[])`,
      [clusterId, memberIds]
    );
  }
}

3. Small-classifier training loop
For each field (sector, job_family, seniority, employment_type), train a multinomial logistic regression on the 384-dim embedding.
ts
// classifier.ts
import { pool } from './db';
import LogisticRegression from 'ml-logistic-regression';
import { Matrix } from 'ml-matrix';


type FieldName = 'sector' | 'job_family' | 'seniority' | 'employment_type';


const FIELDS: FieldName[] = ['sector', 'job_family', 'seniority', 'employment_type'];


type Model = {
  field: FieldName;
  classes: string[];
  model: LogisticRegression;
  featureDim: number;
};


const models: Record<string, Model> = {};


async function loadTrainingData(field: FieldName) {
  const { rows } = await pool.query(
    `
    select e.embedding, l.value
    from labels l
    join clusters c on c.id = l.cluster_id
    join embeddings e on e.posting_id = c.representative_posting_id
    where l.field = $1
      and l.confidence >= 0.9
      and l.value is not null
    `,
    [field]
  );


  const X: number[][] = [];
  const y: string[] = [];
  for (const r of rows) {
    const vec = r.embedding.replace(/[\[\]]/g, '').split(',').map(Number);
    X.push(vec);
    y.push(r.value);
  }
  return { X, y };
}


export async function trainFieldClassifiers() {
  const metrics: Record<string, any> = {};


  for (const field of FIELDS) {
    const { X, y } = await loadTrainingData(field);
    if (X.length < 30) {
      metrics[field] = { skipped: true, n: X.length };
      continue;
    }


    const classes = Array.from(new Set(y));
    const classIndex = new Map(classes.map((c, i) => [c, i]));
    const yIdx = y.map((v) => classIndex.get(v)!);


    const xMatrix = new Matrix(X);
    const yMatrix = Matrix.columnVector(yIdx);


    const model = new LogisticRegression({
      numSteps: 500,
      learningRate: 0.05,
      maxIterations: 1000,
    });


    model.train(xMatrix, yMatrix);


    models[field] = {
      field,
      classes,
      model,
      featureDim: X[0].length,
    };


    // simple in-sample accuracy
    const preds = model.predict(xMatrix);
    let correct = 0;
    for (let i = 0; i < preds.length; i++) {
      if (preds[i] === yIdx[i]) correct++;
    }
    metrics[field] = {
      n: X.length,
      classes: classes.length,
      trainAccuracy: correct / yIdx.length,
    };
  }


  return metrics;
}


export function predictField(field: FieldName, embedding: number[]) {
  const m = models[field];
  if (!m) return null;
  const x = new Matrix([embedding]);
  const probs = m.model.predict(x, { probability: true }) as number[][];
  const row = probs[0];
  let best = 0;
  for (let i = 1; i < row.length; i++) if (row[i] > row[best]) best = i;
  return {
    value: m.classes[best],
    confidence: row[best],
    source: 'ml' as const,
  };
}


export async function evaluateClassifiers() {
  const out: Record<string, any> = {};
  for (const field of FIELDS) {
    if (!models[field]) continue;
    const { X, y } = await loadTrainingData(field);
    const m = models[field];
    const x = new Matrix(X);
    const preds = m.model.predict(x);
    let correct = 0;
    for (let i = 0; i < preds.length; i++) {
      const predLabel = m.classes[preds[i]];
      if (predLabel === y[i]) correct++;
    }
    out[field] = { n: X.length, accuracy: correct / y.length };
  }
  return out;
}

import * as tf from '@tensorflow/tfjs-node';


export function buildMlp(inputDim: number, numClasses: number) {
  const model = tf.sequential();
  model.add(tf.layers.dense({ inputShape: [inputDim], units: 128, activation: 'relu' }));
  model.add(tf.layers.dropout({ rate: 0.2 }));
  model.add(tf.layers.dense({ units: 64, activation: 'relu' }));
  model.add(tf.layers.dense({ units: numClasses, activation: 'softmax' }));
  model.compile({
    optimizer: tf.train.adam(0.001),
    loss: 'sparseCategoricalCrossentropy',
    metrics: ['accuracy'],
  });
  return model;
}

const UNCERTAINTY_THRESHOLD = 0.85;

export async function enqueueUncertain() {
  const { rows } = await pool.query(
    `select c.id, c.representative_posting_id
     from clusters c
     where c.needs_teacher = true
       and not exists (
         select 1 from teacher_calls t where t.cluster_id = c.id
       )
     limit 500`
  );


  for (const c of rows) {
    const { rows: p } = await pool.query(
      `select raw_text from postings where id = $1`,
      [c.representative_posting_id]
    );
    const prompt = buildTeacherPrompt(p[0].raw_text);


    await boss.send('teacher', { clusterId: c.id, prompt }, {
      retryLimit: 3,
      retryBackoff: true,
      expireInMinutes: 10,
    });
  }
}


export async function classifyCluster(clusterId: number) {
  const { rows } = await pool.query(
    `select e.embedding
     from clusters c
     join embeddings e on e.posting_id = c.representative_posting_id
     where c.id = $1`,
    [clusterId]
  );
  if (!rows[0]) return null;


  const embedding = rows[0].embedding.replace(/[\[\]]/g, '').split(',').map(Number);


  const result: Record<string, any> = {};
  let needsTeacher = false;


  for (const field of Object.keys(models) as any[]) {
    const pred = predictField(field, embedding);
    if (!pred) {
      needsTeacher = true;
      continue;
    }
    if (pred.confidence >= AUTO_ACCEPT) {
      result[field] = pred;
    } else if (pred.confidence >= UNCERTAINTY_THRESHOLD) {
      // send to small local LLM instead
      result[field] = { ...pred, source: 'small_llm_pending' };
    } else {
      needsTeacher = true;
    }
  }


  await pool.query(
    `update clusters set needs_teacher = $1 where id = $2`,
    [needsTeacher, clusterId]
  );


  return result;
}


export async function runActiveLearningRound() {
  const { rows: clusters } = await pool.query(
    `select id from clusters where label is null or confidence is null limit 1000`
  );


  for (const c of clusters) {
    await classifyCluster(c.id);
  }


  await enqueueUncertain();
  await boss.send('train', {});
}

ts
// eval.ts
import { pool } from './db';
import { predictField, models } from './classifier';


export async function holdoutEval(field: string, holdoutFrac = 0.2) {
  const { rows } = await pool.query(
    `
    select e.embedding, l.value
    from labels l
    join clusters c on c.id = l.cluster_id
    join embeddings e on e.posting_id = c.representative_posting_id
    where l.field = $1 and l.confidence >= 0.9
    `,
    [field]
  );


  const shuffled = rows.sort(() => Math.random() - 0.5);
  const cut = Math.floor(shuffled.length * (1 - holdoutFrac));
  const test = shuffled.slice(cut);


  let correct = 0;
  let abstained = 0;
  for (const r of test) {
    const vec = r.embedding.replace(/[\[\]]/g, '').split(',').map(Number);
    const pred = predictField(field as any, vec);
    if (!pred || pred.confidence < 0.85) {
      abstained++;
      continue;
    }
    if (pred.value === r.value) correct++;
  }


  const answered = test.length - abstained;
  return {
    field,
    n: test.length,
    answered,
    abstained,
    accuracy: answered > 0 ? correct / answered : null,
    coverage: answered / test.length,
  };
}
Run this every few rounds. If accuracy drops below your bar, raise the uncertainty threshold and route more to the teacher.

'use server';


import { revalidatePath } from 'next/cache';
import { getSupabase } from '@/lib/supabase/server';


export async function decideLabel(formData: FormData) {
  const supabase = await getSupabase();
  const {
    data: { user },
  } = await supabase.auth.getUser();
  if (!user) throw new Error('unauthenticated');


  const labelId = String(formData.get('labelId'));
  const orgId = String(formData.get('orgId'));
  const action = String(formData.get('action')); // approve | reject | edit
  const edited = formData.get('value');
  const notes = formData.get('notes');


  const patch: Record<string, unknown> = {
    reviewed_by: user.id,
    reviewed_at: new Date().toISOString(),
    review_notes: notes ? String(notes) : null,
  };


  if (action === 'approve') {
    patch.review_status = 'approved';
  } else if (action === 'reject') {
    patch.review_status = 'rejected';
  } else if (action === 'edit') {
    patch.review_status = 'edited';
    patch.original_value = formData.get('originalValue');
    patch.value = edited ? String(edited) : null;
  }


  const { error } = await supabase
    .from('labels')
    .update(patch)
    .eq('id', labelId)
    .eq('org_id', orgId);


  if (error) throw new Error(error.message);
  revalidatePath('/review');
}


export async function bulkApprove(formData: FormData) {
  const supabase = await getSupabase();
  const {
    data: { user },
  } = await supabase.auth.getUser();
  if (!user) throw new Error('unauthenticated');


  const orgId = String(formData.get('orgId'));

4. Bulk approve endpoint
Put this behind a cron or an admin-only route. It only approves labels above a confidence floor, so the human review budget goes to the ambiguous cases.
ts
// app/api/review/bulk/route.ts
import { NextRequest } from 'next/server';
import { getSupabase } from '@/lib/supabase/server';


export async function POST(req: NextRequest) {
  const supabase = await getSupabase();
  const {
    data: { user },
  } = await supabase.auth.getUser();
  if (!user) return new Response('unauthenticated', { status: 401 });


  const { orgId, field, minConfidence } = await req.json();


  const { error, count } = await supabase
    .from('labels')
    .update({
      review_status: 'approved',
      reviewed_by: user.id,
      reviewed_at: new Date().toISOString(),
    })
    .eq('org_id', orgId)
    .eq('field', field)
    .eq('review_status', 'pending')
    .gte('confidence', minConfidence)
    .select('id', { count: 'exact' });


  if (error) return new Response(error.message, { status: 400 });
  return Response.json({ approved: count });
}
5. How it fits together
text
scraper / import
  → ingest worker (service role, bypasses RLS)
  → embed worker
  → cluster worker (HDBSCAN)
  → classifier worker (rules + ML + kNN)
  → uncertain clusters → teacher worker
  → labels inserted as review_status = 'pending'
  → /review UI (RLS-scoped to the user's org)
  → approved/edited labels flow into training_labels
  → next train run reads training_labels
  → classifier improves, teacher calls drop
Two guarantees that matter:
* RLS means an AkiliBrain user in org A can never see or approve org B’s labels, even if they guess a label ID.
* The training_labels view means nothing the teacher said reaches the classifier until a human signs off.
If you want the next piece, the natural follow-ons are: a labeling-metrics dashboard (coverage, accuracy per field, teacher-call savings over time), or a batch review mode that groups pending labels by cluster so you approve one label and propagate it to the whole cluster in a single click.

1. Schema additions
Cluster-level labels are what you approve. Posting-level labels are derived. Track that split explicitly.
sql
-- 0004_cluster_labels.sql


-- Cluster-level label = the authoritative decision for a semantic template.
create table cluster_labels (
  id bigserial primary key,
  org_id uuid not null references organizations(id) on delete cascade,
  cluster_id bigint not null references clusters(id) on delete cascade,
  field text not null,
  value text,
  confidence real,
  source text not null,              -- rule | ml | knn | small_llm | teacher
  review_status text not null default 'pending'
    check (review_status in ('pending','approved','rejected','edited')),
  reviewed_by uuid references auth.users(id),
  reviewed_at timestamptz,
  review_notes text,
  original_value text,
  created_at timestamptz default now(),
  unique (cluster_id, field)
);


create index on cluster_labels (org_id, review_status);
create index on cluster_labels (org_id, field);


alter table cluster_labels enable row level security;


create policy "clabel_read"  on cluster_labels for select using (is_org_member(org_id));
create policy "clabel_write" on cluster_labels for all
  using (is_org_editor(org_id)) with check (is_org_editor(org_id));


-- Training view now reads from approved cluster labels.
create or replace view training_cluster_labels as
select *
from cluster_labels
where review_status in ('approved','edited')

  and confidence >= 0.9;

The derived_from_cluster_label_id FK is the trick: if you later edit a cluster label, you delete and re-derive every posting label that points to it.
2. Batch review action (approve cluster, propagate)
ts
// app/review/batch-actions.ts
'use server';


import { revalidatePath } from 'next/cache';
import { getSupabase } from '@/lib/supabase/server';


export async function approveClusterLabel(formData: FormData) {
  const supabase = await getSupabase();
  const {
    data: { user },
  } = await supabase.auth.getUser();
  if (!user) throw new Error('unauthenticated');


  const orgId = String(formData.get('orgId'));
  const clusterLabelId = String(formData.get('clusterLabelId'));
  const action = String(formData.get('action')); // approve | reject | edit
  const edited = formData.get('value');
  const notes = formData.get('notes');


  const patch: Record<string, unknown> = {
    reviewed_by: user.id,
    reviewed_at: new Date().toISOString(),
    review_notes: notes ? String(notes) : null,
  };


  if (action === 'approve') patch.review_status = 'approved';
  else if (action === 'reject') patch.review_status = 'rejected';
  else if (action === 'edit') {
    patch.review_status = 'edited';
    patch.original_value = formData.get('originalValue');
    patch.value = edited ? String(edited) : null;
  }


  const { data: label, error } = await supabase
    .from('cluster_labels')
    .update(patch)
    .eq('id', clusterLabelId)
    .eq('org_id', orgId)
    .select('id, cluster_id, field, value, confidence, source, review_status')
    .single();


  if (error) throw new Error(error.message);


  if (label.review_status === 'approved' || label.review_status === 'edited') {
    await propagateClusterLabel(label);
  } else {
    await clearPostingLabels(label.id);
  }


  revalidatePath('/review');
  revalidatePath('/review/batch');
}


async function propagateClusterLabel(label: {
  id: number;
  cluster_id: number;
  field: string;
  value: string | null;
  confidence: number | null;
  source: string;
}) {
  const supabase = await getSupabase();


  // Remove stale derivations, then insert fresh ones.
  await supabase
    .from('posting_labels')
    .delete()
    .eq('derived_from_cluster_label_id', label.id);


  const { data: members } = await supabase
    .from('cluster_members')
    .select('posting_id, org_id')
    .eq('cluster_id', label.cluster_id);


  if (!members?.length) return;


  const rows = members.map((m) => ({
    org_id: m.org_id,
    posting_id: m.posting_id,
    cluster_id: label.cluster_id,
    field: label.field,
    value: label.value,
    confidence: label.confidence,
    source: label.source,
    derived_from_cluster_label_id: label.id,
  }));


  const { error } = await supabase
    .from('posting_labels')
    .upsert(rows, { onConflict: 'posting_id,field' });


  if (error) throw new Error(error.message);
}


async function clearPostingLabels(clusterLabelId: number) {
  const supabase = await getSupabase();
  await supabase
    .from('posting_labels')
    .delete()
    .eq('derived_from_cluster_label_id', clusterLabelId);
}
For a large cluster (say 800 members), the upsert runs server-side inside one Supabase statement. No N round trips from the browser.

4. Metrics
Two views, one for coverage and one for savings.
sql
-- 0005_metrics_views.sql


-- Per-field coverage and source mix.
create or replace view field_coverage as
select
  pl.org_id,
  pl.field,
  count(*) filter (where pl.source = 'rule')         as from_rule,
  count(*) filter (where pl.source = 'ml')           as from_ml,
  count(*) filter (where pl.source = 'knn')          as from_knn,
  count(*) filter (where pl.source = 'small_llm')    as from_small_llm,
  count(*) filter (where pl.source = 'teacher')      as from_teacher,
  count(*)                                           as total,
  avg(pl.confidence)                                 as avg_confidence
from posting_labels pl
group by pl.org_id, pl.field;


-- Cluster-level review progress.
create or replace view review_progress as
select
  org_id,
  field,
  count(*) filter (where review_status = 'pending')  as pending,
  count(*) filter (where review_status = 'approved') as approved,
  count(*) filter (where review_status = 'edited')   as edited,
  count(*) filter (where review_status = 'rejected') as rejected,
  count(*)                                            as total
from cluster_labels
group by org_id, field;


-- Teacher-call savings per round.
create or replace view teacher_savings as
select
  org_id,
  date_trunc('day', created_at) as day,
  count(*) as teacher_calls
from teacher_calls
group by org_id, day
order by day desc;


-- Per-field accuracy against approved cluster labels, using the classifier's own predictions.
-- Assumes you log predictions into a table (see prediction_log below).
create or replace view classifier_accuracy as
select
  org_id,
  field,
  count(*) filter (where correct) as correct,
  count(*)                         as n,
  avg(case when correct then 1 else 0 end) as accuracy
from prediction_log
where evaluated = true
group by org_id, field;
Log every classifier prediction and its later ground truth:
sql
create table prediction_log (
  id bigserial primary key,
  org_id uuid not null references organizations(id) on delete cascade,
  cluster_id bigint not null,
  field text not null,
  predicted_value text,
  predicted_confidence real,
  ground_truth_value text,
  correct boolean,
  evaluated boolean default false,
  created_at timestamptz default now()
);


create index on prediction_log (org_id, field, evaluated);

A nightly job reconciles predictions against approved labels:
ts
// jobs/reconcile-predictions.ts
import { pool } from '../db';


export async function reconcilePredictions() {
  await pool.query(`
    with truth as (
      select org_id, cluster_id, field, value
      from training_cluster_labels
    )
    update prediction_log p
    set ground_truth_value = t.value,
        correct = (p.predicted_value is not distinct from t.value),
        evaluated = true
    from truth t
    where p.org_id = t.org_id
      and p.cluster_id = t.cluster_id
      and p.field = t.field
      and p.evaluated = false
  `);
}

// jobs/accuracy-drift.ts
import { pool } from '../db';


export async function accuracyDrift(orgId: string) {
  const { rows } = await pool.query(
    `
    with weekly as (
      select
        field,
        date_trunc('week', created_at) as week,
        avg(case when correct then 1 else 0 end) as acc,
        count(*) as n
      from prediction_log
      where org_id = $1
        and evaluated = true
        and created_at > now() - interval '8 weeks'
      group by field, week
    ),
    ranked as (
      select *,
        row_number() over (partition by field order by week desc) as rn
      from weekly
    )
    select
      a.field,
      a.acc as this_week,
      b.acc as last_week,
      a.acc - b.acc as delta,
      a.n as n_this_week
    from ranked a
    join ranked b on a.field = b.field and a.rn = 1 and b.rn = 2
    where a.n >= 20
    order by delta asc
    `,
    [orgId]
  );
  return rows.filter((r: any) => Number(r.delta) < -0.05);
}

2. Semantic merge check
The scenario: reviewer approves label sector = health for cluster A. Two weeks later, cluster B (which was generated from a slightly different embedding region) gets sector = healthcare. Those are the same thing. Your classifier is now learning to discriminate between them, which is wasted capacity and a source of noise.
The fix is a merge-candidates job that compares approved cluster labels against each other and surfaces pairs above a similarity threshold.

// jobs/detect-merge-candidates.ts
import { pool } from '../db';


export async function detectMergeCandidates(orgId: string, similarityFloor = 0.93) {
  const { rowCount } = await pool.query(
    `
    with approved as (
      select
        cl.org_id,
        cl.field,
        cl.cluster_id,
        cl.value as label,
        cc.centroid
      from cluster_labels cl
      join cluster_centroids cc on cc.cluster_id = cl.cluster_id
      where cl.org_id = $1
        and cl.review_status in ('approved','edited')
        and cl.value is not null
    )
    insert into merge_candidates
      (org_id, field, cluster_a, cluster_b, label_a, label_b, embedding_similarity)
    select
      a.org_id,
      a.field,
      least(a.cluster_id, b.cluster_id)    as cluster_a,
      greatest(a.cluster_id, b.cluster_id) as cluster_b,
      a.label,
      b.label,
      1 - (a.centroid <=> b.centroid)      as embedding_similarity
    from approved a
    join approved b
      on a.org_id = b.org_id
     and a.field  = b.field
     and a.cluster_id < b.cluster_id
     and a.label <> b.label
    where 1 - (a.centroid <=> b.centroid) >= $2
    on conflict (org_id, field, cluster_a, cluster_b) do update
      set embedding_similarity = excluded.embedding_similarity,
          label_a = excluded.label_a,
          label_b = excluded.label_b,
          detection_run = now()
      where merge_candidates.status = 'pending'
    `,
    [orgId, similarityFloor]
  );
  return { candidates: rowCount };
}
Two things to note.
First, <=> is pgvector cosine distance, so 1 - <=> is cosine similarity, same convention as the earlier kNN code.
Second, the on conflict ... where status = 'pending' clause means a candidate that a human already dismissed stays dismissed. Only genuinely new pairs, or pairs that were never reviewed, get inserted.
3. Merge / dismiss actions
Merging is not a delete. It preserves the losing cluster's members, moves them to the surviving cluster, and re-derives posting labels.
ts
// jobs/merge-clusters.ts
import { pool } from '../db';


export async function mergeClusters(args: {
  orgId: string;
  field: string;
  survivorId: number;
  loserId: number;
  userId: string;
}) {
  const client = await pool.connect();
  try {
    await client.query('begin');


    // Move members. on conflict do nothing in case a posting is already in both.
    await client.query(
      `
      insert into cluster_members (org_id, cluster_id, posting_id)
      select org_id, $1, posting_id
      from cluster_members
      where cluster_id = $2
      on conflict do nothing
      `,
      [args.survivorId, args.loserId]
    );


    await client.query(`delete from cluster_members where cluster_id = $1`, [args.loserId]);


    // Update size on survivor, zero out loser.
    await client.query(
      `update clusters set size = (select count(*) from cluster_members where cluster_id = $1) where id = $1`,
      [args.survivorId]
    );
    await client.query(`update clusters set size = 0 where id = $1`, [args.loserId]);


    // Re-derive posting labels for the survivor's full membership, using its approved label.
    await client.query(
      `
      delete from posting_labels
      where cluster_id = $1
        and field = $2
      `,
      [args.survivorId, args.field]
    );


    await client.query(
      `
      insert into posting_labels
        (org_id, posting_id, cluster_id, field, value, confidence, source, derived_from_cluster_label_id)
      select
        cm.org_id,
        cm.posting_id,
        $1,
        cl.field,
        cl.value,
        cl.confidence,
        cl.source,
        cl.id
      from cluster_members cm
      join cluster_labels cl
        on cl.cluster_id = $1
       and cl.field = $2
       and cl.review_status in ('approved','edited')
      where cm.cluster_id = $1
      on conflict (posting_id, field) do update
        set value = excluded.value,
            confidence = excluded.confidence,
            source = excluded.source,
            derived_from_cluster_label_id = excluded.derived_from_cluster_label_id,
            cluster_id = excluded.cluster_id
      `,
      [args.survivorId, args.field]
    );


    // Mark the merge record.
    await client.query(
      `
      update merge_candidates
      set status = 'merged',
          reviewed_by = $1,
          reviewed_at = now()
      where field = $2
        and cluster_a = least($3::bigint, $4::bigint)
        and cluster_b = greatest($3::bigint, $4::bigint)
      `,
      [args.userId, args.field, args.survivorId, args.loserId]
    );


    // Any other pending candidates involving the loser are now moot.
    await client.query(
      `
      update merge_candidates
      set status = 'dismissed',
          reviewed_by = $1,
          reviewed_at = now()
      where status = 'pending'
        and (cluster_a = $2 or cluster_b = $2)
      `,
      [args.userId, args.loserId]
    );


    await client.query('commit');
  } catch (err) {
    await client.query('rollback');
    throw err;
  } finally {
    client.release();
  }
}
The whole thing runs in one transaction. If anything fails halfway, you do not end up with a cluster that has members but no label, or a label that points to postings that have moved elsewhere.

// app/review/merge-actions.ts
'use server';


import { revalidatePath } from 'next/cache';
import { getSupabase } from '@/lib/supabase/server';
import { mergeClusters } from '@/jobs/merge-clusters';


export async function resolveMergeCandidate(formData: FormData) {
  const supabase = await getSupabase();
  const {
    data: { user },
  } = await supabase.auth.getUser();
  if (!user) throw new Error('unauthenticated');


  const orgId = String(formData.get('orgId'));
  const candidateId = String(formData.get('candidateId'));
  const action = String(formData.get('action')); // merge | dismiss
  const survivorId = Number(formData.get('survivorId'));
  const field = String(formData.get('field'));


  const { data: candidate, error: readErr } = await supabase
    .from('merge_candidates')
    .select('id, cluster_a, cluster_b')
    .eq('id', candidateId)
    .eq('org_id', orgId)
    .single();


  if (readErr || !candidate) throw new Error('candidate not found');


  const loserId =
    survivorId === candidate.cluster_a ? candidate.cluster_b : candidate.cluster_a;


  if (action === 'merge') {
    await mergeClusters({
      orgId,
      field,
      survivorId,
      loserId,
      userId: user.id,
    });
  } else {
    await supabase
      .from('merge_candidates')
      .update({
        status: 'dismissed',
        reviewed_by: user.id,
        reviewed_at: new Date().toISOString(),
      })
      .eq('id', candidateId)
      .eq('org_id', orgId);
  }


  revalidatePath('/review/merges');
}

// jobs/digest.ts
import { pool } from '../db';
import { accuracyDrift } from './accuracy-drift';


type Digest = {
  orgId: string;
  orgName: string;
  drift: Array<{ field: string; delta: number; thisWeek: number; lastWeek: number; n: number }>;
  pendingReviews: number;
  pendingMerges: number;
  teacherCallsYesterday: number;
  localShare: number;
};


export async function buildDigest(orgId: string): Promise<Digest> {
  const [{ rows: org }, { rows: progress }, { rows: merges }, { rows: savings }, { rows: coverage }] =
    await Promise.all([
      pool.query(`select name from organizations where id = $1`, [orgId]),
      pool.query(
        `select coalesce(sum(pending), 0) as pending from review_progress where org_id = $1`,
        [orgId]
      ),
      pool.query(
        `select count(*)::int as n from merge_candidates where org_id = $1 and status = 'pending'`,
        [orgId]
      ),
      pool.query(
        `select count(*)::int as n from teacher_calls
         where org_id = $1 and created_at >= now() - interval '1 day'`,
        [orgId]
      ),
      pool.query(
        `select
           coalesce(sum(from_rule + from_ml + from_knn), 0) as local,
           coalesce(sum(total), 0) as total
         from field_coverage where org_id = $1`,
        [orgId]
      ),
    ]);


  const drift = await accuracyDrift(orgId);
  const local = Number(coverage[0]?.local ?? 0);
  const total = Number(coverage[0]?.total ?? 0);


  return {
    orgId,
    orgName: org[0]?.name ?? 'unknown',
    drift,
    pendingReviews: Number(progress[0]?.pending ?? 0),
    pendingMerges: Number(merges[0]?.n ?? 0),
    teacherCallsYesterday: Number(savings[0]?.n ?? 0),
    localShare: total > 0 ? local / total : 0,
  };
}

2. Backfill historical merges
This runs once, on demand. It re-runs detection against every approved cluster label in an org, not just the ones that changed recently. Useful after you raise or lower the similarity floor, or after importing a batch of historical labels.
ts
// jobs/backfill-merges.ts
import { pool } from '../db';
import { detectMergeCandidates } from './detect-merge-candidates';


export async function backfillMerges(args: {
  orgId: string;
  similarityFloor?: number;
  batchSize?: number;
}) {
  const floor = args.similarityFloor ?? 0.93;
  const batchSize = args.batchSize ?? 1000;


  let offset = 0;
  let totalInserted = 0;


  while (true) {
    const { rows } = await pool.query(
      `
      select cluster_id
      from cluster_labels
      where org_id = $1
        and review_status in ('approved','edited')
        and value is not null
      order by cluster_id
      limit $2 offset $3
      `,
      [args.orgId, batchSize, offset]
    );


    if (rows.length === 0) break;


    const result = await detectMergeCandidates(args.orgId, floor);
    totalInserted += result.candidates ?? 0;


    offset += rows.length;
    console.log(`backfill offset=${offset} inserted=${result.candidates}`);
  }


  return { totalInserted };
}
The offset loop matters because detectMergeCandidates compares all approved labels at once. If you have 20,000 approved clusters, the cross-join is large. Running it once per org is fine for a one-off, but if you hit a statement timeout, add a per-cluster variant:
ts
// jobs/backfill-merges-windowed.ts
import { pool } from '../db';


export async function backfillMergesWindowed(orgId: string, floor = 0.93) {
  const { rows: anchors } = await pool.query(
    `
    select cl.cluster_id, cl.field, cl.value as label, cc.centroid
    from cluster_labels cl
    join cluster_centroids cc on cc.cluster_id = cl.cluster_id
    where cl.org_id = $1
      and cl.review_status in ('approved','edited')
      and cl.value is not null
    `,
    [orgId]
  );


  let inserted = 0;


  for (const a of anchors) {
    const { rowCount } = await pool.query(
      `
      insert into merge_candidates
        (org_id, field, cluster_a, cluster_b, label_a, label_b, embedding_similarity)
      select
        $1,
        $2,
        least($3::bigint, other.cluster_id)    as cluster_a,
        greatest($3::bigint, other.cluster_id) as cluster_b,
        $4,
        other.value,
        1 - ($5::vector <=> other.centroid)    as embedding_similarity
      from (
        select cl.cluster_id, cl.value, cc.centroid
        from cluster_labels cl
        join cluster_centroids cc on cc.cluster_id = cl.cluster_id
        where cl.org_id = $1
          and cl.field = $2
          and cl.review_status in ('approved','edited')
          and cl.value is not null
          and cl.cluster_id > $3
          and cl.value <> $4
      ) other
      where 1 - ($5::vector <=> other.centroid) >= $6
      on conflict (org_id, field, cluster_a, cluster_b) do nothing
      `,
      [orgId, a.field, a.cluster_id, a.label, a.centroid, floor]
    );
    inserted += rowCount ?? 0;
  }


  return { inserted };
}
The windowed version trades many small queries for one large query. On Supabase's free tier with statement timeouts around 2 minutes, windowed is the safer choice.

const Schema = z.object({

export async function cachedTeacherCall(clusterId: number, prompt: string) {
  const promptHash = crypto.createHash('sha256').update(prompt).digest('hex');


  const { rows } = await pool.query(
    `select response from teacher_calls where prompt_hash = $1 limit 1`,
    [promptHash]
  );

    prompt,
    temperature: 0,
  });

      usage?.totalTokens ?? null,

3. The savings query
Three numbers matter:
* Actual cost — what the teacher calls cost at list price. You paid $0 because you used free tiers, but this is what it would have cost on pay-as-you-go.
* Naive cost — what one 70B call per posting would have cost, using the same average prompt and completion sizes.
* Avoided cost — the delta.
sql
-- 0011_savings_report.sql


create or replace view savings_report as
with actual as (
  select
    tc.org_id,
    count(*) as teacher_calls,
    sum(coalesce(tc.prompt_tokens, 0))     as prompt_tokens,
    sum(coalesce(tc.completion_tokens, 0)) as completion_tokens,
    sum(
      coalesce(tc.prompt_tokens, 0)     / 1e6 * mp.input_per_million +
      coalesce(tc.completion_tokens, 0) / 1e6 * mp.output_per_million
    ) as actual_cost_usd
  from teacher_calls tc
  left join model_pricing mp on mp.model = tc.model
  group by tc.org_id
),
naive as (
  select
    org_id,
    count(*) as total_postings,
    -- Apply the actual average tokens per call to every posting.
    count(*) * (select avg(coalesce(prompt_tokens, 0)) from teacher_calls where org_id = a.org_id)     as prompt_tokens,
    count(*) * (select avg(coalesce(completion_tokens, 0)) from teacher_calls where org_id = a.org_id) as completion_tokens
  from postings a
  group by org_id
)
select
  a.org_id,
  a.teacher_calls,
  n.total_postings,
  n.prompt_tokens     as naive_prompt_tokens,
  n.completion_tokens as naive_completion_tokens,
  a.actual_cost_usd,
  n.prompt_tokens     / 1e6 * (select max(input_per_million)  from model_pricing where model = 'llama-3.3-70b-versatile')
    + n.completion_tokens / 1e6 * (select max(output_per_million) from model_pricing where model = 'llama-3.3-70b-versatile')
    as naive_cost_usd,
  (
    n.prompt_tokens     / 1e6 * (select max(input_per_million)  from model_pricing where model = 'llama-3.3-70b-versatile')
    + n.completion_tokens / 1e6 * (select max(output_per_million) from model_pricing where model = 'llama-3.3-70b-versatile')
  ) - a.actual_cost_usd as avoided_cost_usd,
  case
    when n.total_postings > 0 then 1.0 - (a.teacher_calls::numeric / n.total_postings)
    else 0
  end as reduction_ratio
from actual a
join naive n on n.org_id = a.org_id;
The reduction_ratio is the headline number. If it is 0.97, the pipeline eliminated 97% of the naive 70B workload.

1. Per-field attribution
The savings report answers "how much did the pipeline avoid overall." This view answers "which stage did the work, per field." That tells you where to invest next.
sql
-- 0012_field_savings.sql


create or replace view field_savings as
with label_sources as (
  select
    pl.org_id,
    pl.field,
    count(*) filter (where pl.source = 'rule')      as from_rule,
    count(*) filter (where pl.source = 'ml')        as from_ml,
    count(*) filter (where pl.source = 'knn')       as from_knn,
    count(*) filter (where pl.source = 'small_llm') as from_small_llm,
    count(*) filter (where pl.source = 'teacher')   as from_teacher,
    count(*)                                         as total
  from posting_labels pl
  group by pl.org_id, pl.field
),
token_rates as (
  select
    org_id,
    field,
    avg(prompt_tokens)     filter (where true) as avg_prompt_tokens,
    avg(completion_tokens) filter (where true) as avg_completion_tokens
  from (
    select
      tc.org_id,
      cl.field,
      tc.prompt_tokens,
      tc.completion_tokens
    from teacher_calls tc
    join cluster_labels cl on cl.cluster_id = tc.cluster_id
  ) t
  group by org_id, field
),
pricing as (
  select
    max(input_per_million)  filter (where model = 'llama-3.3-70b-versatile') as in_rate,
    max(output_per_million) filter (where model = 'llama-3.3-70b-versatile') as out_rate
  from model_pricing
)
select
  ls.org_id,
  ls.field,
  ls.total,
  ls.from_rule,
  ls.from_ml,
  ls.from_knn,
  ls.from_small_llm,
  ls.from_teacher,
  -- Naive cost: every row at teacher rates.
  ls.total * coalesce(tr.avg_prompt_tokens, 1800) / 1e6 * p.in_rate
    + ls.total * coalesce(tr.avg_completion_tokens, 180) / 1e6 * p.out_rate
    as naive_cost_usd,
  -- Actual cost: only rows that hit the teacher.
  ls.from_teacher * coalesce(tr.avg_prompt_tokens, 1800) / 1e6 * p.in_rate
    + ls.from_teacher * coalesce(tr.avg_completion_tokens, 180) / 1e6 * p.out_rate
    as actual_cost_usd,
  -- Avoided cost.
  (ls.total - ls.from_teacher) * coalesce(tr.avg_prompt_tokens, 1800) / 1e6 * p.in_rate
    + (ls.total - ls.from_teacher) * coalesce(tr.avg_completion_tokens, 180) / 1e6 * p.out_rate
    as avoided_cost_usd,
  -- Which stage did the work, as a share.
  (ls.from_rule)::numeric      / nullif(ls.total, 0) as share_rule,
  (ls.from_ml)::numeric        / nullif(ls.total, 0) as share_ml,
  (ls.from_knn)::numeric       / nullif(ls.total, 0) as share_knn,
  (ls.from_small_llm)::numeric / nullif(ls.total, 0) as share_small_llm,
  (ls.from_teacher)::numeric   / nullif(ls.total, 0) as share_teacher
from label_sources ls
cross join pricing p
left join token_rates tr on tr.org_id = ls.org_id and tr.field = ls.field;

can you be more clever than this?
The architecture proposed in "clever answers.docx" is a masterclass in data engineering. It successfully reduces reliance on the 70B model by building a sophisticated pipeline of vector embeddings, HDBSCAN clustering, active learning loops, pg-boss queues, and human-in-the-loop Next.js review UIs.
But it is also a massive, over-engineered trap. It builds a beautiful, complex Rube Goldberg machine to solve an NLP problem that doesn't actually need to be an NLP problem.
The fundamental flaw in that document's approach is treating 50,000 scraped job descriptions as unique, unstructured natural language. They aren't. 99% of job postings on the internet are predictably structured HTML emitted by a few dozen Applicant Tracking Systems (ATS) — like Workday, Greenhouse, Lever, and Ashby — or standard job board CMS templates.
Here is the genuinely more clever approach: Stop trying to semantically read 50,000 jobs. Reverse-engineer the 50 templates that generated them.
Instead of using the 70B LLM as a data-entry clerk, use it as a Senior Developer to write deterministic parsers.
1. Cluster by DOM Structure, Not Vector Semantics
You don't need a heavy 384-dimension local embedding model (@xenova/transformers) and a complex vector database (pgvector) to find similar jobs. You just need to look at the HTML structure.
Take your 50,000 raw HTML files and run a fast, local script to strip out all the text, leaving only the HTML tags, IDs, and CSS classes. Hash that resulting skeletal string.
JavaScript
import * as cheerio from 'cheerio';
import crypto from 'crypto';


function getStructuralFingerprint(html) {
  const $ = cheerio.load(html);
  $('*').contents().filter(function() {
    return this.type === 'text'; // Remove all actual text
  }).remove();
  
  // Hash the remaining skeleton (just tags and classes)
  return crypto.createHash('md5').update($.html()).digest('hex');
}
Your 50,000 job descriptions will instantly collapse into roughly 40 to 100 perfect structural clusters based on the ATS or job board that hosted them. This runs locally on a basic laptop in seconds. Zero ML required.
2. The LLM as a Code Generator
Take exactly one raw HTML example from each of your 50 structural clusters. Send that single example to your free-tier 70B model (Groq, OpenRouter, etc.) with a prompt to write a parser for it.
The Prompt:
"You are an expert Node.js scraper. I will provide a raw HTML job description. Write a highly robust, fault-tolerant Node.js function using cheerio that extracts a JSON object containing: title, seniority, job_family, skills (array), and employment_type.
Return ONLY valid, executable JavaScript code. The function must be named parseJob(html) and return the JSON object."
3. Local Deterministic Execution
You now have 50 generated JavaScript functions. Map them to their structural fingerprint hashes.
Iterate through your 50,000 jobs. For each job, calculate its structural hash, grab the corresponding LLM-written Cheerio function, and execute it locally.
JavaScript
const parsers = {
  'hash_for_greenhouse_template': parseGreenhouseJob,
  'hash_for_workday_template': parseWorkdayJob,
  // ... 48 more
};


const results = jobs.map(job => {
  const hash = getStructuralFingerprint(job.html);
  return parsers[hash](job.html); 
});
JavaScript executes at CPU speed. You will parse all 50,000 job descriptions in about 4 seconds.
4. The Self-Healing Loop
If a parser fails (returns null or throws an error), catch the error. Send the broken HTML and the error stack trace back to the 70B model with the prompt:
"This Cheerio parser failed on this new HTML variant with this error. Rewrite the function to handle this edge case."
Save the updated function and re-run.
Why this beats the previous architecture:
* API Calls: Reduced from ~1,500 (in the "clever answers.docx" active learning loop) to exactly ~50. You won't even come close to touching the most restrictive free-tier rate limits.
* Infrastructure: Reduced from Supabase, Postgres, pgvector, pg-boss, and Vercel hosting to a single Node.js script running in local memory or a cheap SQLite file.
* Maintenance: No human-in-the-loop UI required. No accuracy drift over time. You aren't relying on a probabilistic ML model to guess seniority based on vector proximity; you are deterministically extracting the exact string the employer put in the <div class="job-seniority"> tag.
The previous architecture was about managing scale beautifully. This architecture eliminates the scale entirely.
